# 🛍 Sollers Shop

Современное frontend-приложение (Single Page Application), имитирующее полноценный
интерфейс интернет-магазина: каталог с фильтрами, живой поиск, сортировка и
интерактивная корзина. Каталог хранится **локально** (встроенная база товаров
`src/data/products.ts`), поэтому магазин загружается мгновенно и полностью
работает офлайн — без зависимости от сети и внешних API.

## ✨ Возможности

- **Каталог товаров (Product Grid)** — адаптивная сетка карточек с изображением,
  брендом, названием, рейтингом (звёзды), ценой и кнопкой быстрого добавления в
  корзину.
- **Скелетоны загрузки (Skeleton Loading)** — анимированные заглушки в форме
  карточек вместо скучного спиннера.
- **Умная фильтрация и сортировка**
  - Мгновенный живой поиск по названию с **debounce**-оптимизацией.
  - Фильтр по **категориям** и **брендам** (чекбоксы, данные подтягиваются
    динамически).
  - **Ползунок цены** (dual-thumb range slider) для точного диапазона.
  - Сортировка: «Сначала дешёвые», «Сначала дорогие», «По рейтингу».
- **Интерактивная корзина (Cart Drawer)** — выезжающая панель, управление
  количеством (`+` / `−`), автоудаление при количестве 0, живой счётчик и сумма.
  Содержимое сохраняется в `localStorage`.
- **Обработка сетевых ошибок** — дружелюбное уведомление и кнопка «Повторить
  попытку» вместо падения приложения.

## 🛠 Технологический стек

| Технология | Назначение |
| --- | --- |
| **Vite + React 19 + TypeScript** | Строгая типизация сущностей (`Product`, `CartItem`, `Category`) |
| **Tailwind CSS** | Чистый, современный «SaaS-подобный» дизайн и адаптивная сетка |
| **Zustand** | Глобальное состояние корзины без prop drilling |
| **Lucide React** | Минималистичные иконки |
| **Framer Motion** | Мягкие анимации карточек, корзины и счётчиков |

## 🚀 Запуск

### Вариант 1 — без сервера (просто открыть файл)

В репозитории уже лежит **готовая самодостаточная сборка**: весь JS и CSS
встроены в один HTML-файл. Ничего устанавливать и запускать не нужно —
достаточно открыть файл в браузере:

```
dist/index.html   ←  откройте двойным кликом (или File → Open в браузере)
```

Файл работает по протоколу `file://` без dev-сервера и без статического
хостинга. Каталог встроен локально, поэтому интернет не нужен вовсе.

> Пересобрать этот файл можно командой `npm run build` — плагин
> `vite-plugin-singlefile` инлайнит всё в `dist/index.html`.

### Вариант 2 — режим разработки (Vite dev-сервер)

```bash
# 1. Установить зависимости
npm install

# 2. Запустить dev-сервер (http://localhost:5173) с hot-reload
npm run dev

# 3. Собрать самодостаточный dist/index.html (single-file, для file://)
npm run build

# 3b. Собрать оптимизированную multi-file версию (для хостинга/Pages)
npm run build:pages

# 4. Предпросмотр собранной версии
npm run preview
```

> **Две сборки, один конфиг.** `npm run build` инлайнит весь JS/CSS в один
> `dist/index.html` — удобно открывать по `file://` без сервера.
> `npm run build:pages` делает обычную сборку (крошечный `index.html` + хешируемые
> кешируемые и сжимаемые чанки JS/CSS) — она грузится в разы быстрее на реальном
> хостинге, поэтому её и публикует workflow GitHub Pages.

## 🌐 Публикация на GitHub Pages

В репозитории есть workflow **`.github/workflows/deploy.yml`**, который сам
собирает проект командой `npm run build:pages` (оптимизированная multi-file
сборка) и публикует папку `dist/` на GitHub Pages.

**Настройка (один раз):**

1. Откройте **Settings → Pages** в репозитории.
2. В разделе **Build and deployment → Source** выберите **GitHub Actions**
   (а не «Deploy from a branch»).

После этого при каждом пуше в ветку `main` (или в рабочую ветку проекта)
workflow пересобирает сайт и публикует его по адресу:

```
https://<владелец>.github.io/<репозиторий>/
```

> **Почему раньше была ошибка 404?** GitHub Pages в режиме «Deploy from a
> branch» отдавал корневой `index.html`, который является точкой входа Vite и
> ссылается на исходник `/src/main.tsx` (TypeScript) — такого файла в
> собранном виде нет, поэтому страница не загружалась. Публиковать нужно
> **собранную** папку `dist/`, что и делает workflow.
>
> Пути в сборке относительные (`base: './'`), поэтому сайт корректно работает
> в подпапке `/<репозиторий>/` — менять конфигурацию при переименовании репо
> не нужно.

Запустить публикацию вручную можно на вкладке **Actions → Deploy to GitHub
Pages → Run workflow**.

## 📁 Структура проекта

```
src/
├── data/
│   └── products.ts         # 🗄 Локальная база: товары + категории
├── api/
│   └── products.ts         # Слой доступа к данным (читает из data/)
├── components/
│   ├── PromoBar.tsx        # Верхняя промо-полоса
│   ├── Header.tsx          # Шапка: лого, живой поиск, иконка корзины
│   ├── Hero.tsx            # Баннер-обложка
│   ├── CategoryChips.tsx   # Быстрые чипсы категорий
│   ├── FilterSidebar.tsx   # Категории, бренды, ползунок цены
│   ├── ProductGrid.tsx     # Адаптивная сетка / пустое состояние
│   ├── ProductCard.tsx     # Карточка товара
│   ├── ProductCardSkeleton.tsx  # Скелетон загрузки
│   ├── CartDrawer.tsx      # Выезжающая панель корзины
│   ├── CartItemRow.tsx     # Строка товара в корзине (+/- количество)
│   ├── RangeSlider.tsx     # Двойной ползунок цены
│   ├── SortSelect.tsx      # Выпадающее меню сортировки
│   ├── StarRating.tsx      # Рейтинг звёздами (с дробным заполнением)
│   ├── ErrorState.tsx      # Экран ошибки + «Повторить»
│   ├── ScrollToTop.tsx     # Кнопка «наверх»
│   └── Footer.tsx          # Подвал сайта
├── hooks/
│   ├── useDebounce.ts      # Debounce для живого поиска
│   └── useSmoothScroll.ts  # Плавная прокрутка (Lenis)
├── store/
│   └── cartStore.ts        # Zustand-стор корзины + селекторы
├── utils/
│   ├── catalog.ts          # Генерация вариантов товаров
│   ├── placeholder.ts      # Локальные SVG-заглушки картинок
│   └── format.ts           # Форматирование цены и слагов
├── types.ts                # Доменные интерфейсы
├── App.tsx                 # Корневой компонент, оркестрация состояния
├── main.tsx                # Точка входа React
└── index.css               # Tailwind + кастомные утилиты
```
